* Roadmap

Grouped by priority and action type (=Next= / =Design= / =Later= /
=Non-goals=), with Org tags for topic filtering.

** Next

The next active track: settle the ReSpec vs Bikeshed subset, then
prune and clean =assets/style.css= to match.

*** Heading wrapper and self-link markup (ReSpec vs Bikeshed)    :html:css:

=org-w3ctr-heading-default-format-function= currently wraps every
normal heading in =<div class="header-wrapper">= with =<a
class="self-link">= as a sibling after =<hN>=, which is the *ReSpec*
pattern (as in =rdf12-concepts=): flex + =order: -1= places =§= to the
left aligned to the heading baseline without putting =<a>= inside
=<hN>= (cleaner accessible name), at the cost of an extra wrapper
=<div>= around every heading -- even when =:html-self-link-headlines=
is nil.

The alternative is the *Bikeshed* pattern (as in =CSP3=): no wrapper
=<div>=; emit =<hN class="heading">...<a class="self-link"></a></hN>=
and position =§= to the left with =position: relative= / =absolute=.
Bikeshed's static-compiler model is closer to =ox-w3ctr='s overall
architecture, and =assets/style.css= (L1714--1779) currently carries
spliced rules from both patterns.  When revisiting =assets/style.css=
cleanup, decide between:

- Keeping the ReSpec =.header-wrapper= (optionally omitting the =<div>=
  when =self-link= is nil, scoping =left: -.5em= to
  =.header-wrapper > :is(h2,h3,h4,h5,h6)=); or
- Switching to the Bikeshed wrapper-less =<hN class="heading">= markup
  and dropping the ReSpec =.header-wrapper= CSS rules.

*** CSS cleanup in =assets/style.css=                                 :css:

Not urgent (~50 KB, inlined into every exported document by
=org-w3ctr--load-css=).

- Dead rules: =.org-center= (never emitted).
- Spliced =self-link= / heading block (L1714--1779, from CSP3 and
  rdf12-concepts): undefined =--selflink-bg= / =--selflink-text= /
  =--selflink-hover-text= variables on =dfn > a.self-link=, typo
  =:not(#toch2)= (missing space vs =#toc > h2=), overlapping
  =.self-link:hover= / =::before= rules, and hardcoded =color:#000=
  on =:is(h4,h5,h6)+a.self-link::before= (invisible in dark mode).
- Unify local overrides: fold =pre > code= background (=--src-bg=)
  into the main =:root= light/dark blocks instead of keeping a
  separate =@media (prefers-color-scheme: dark)=.
- Prune unused W3C/Bikeshed rules (~30 classes not emitted by
  =ox-w3ctr.el=): keep author-usable special-block / table hooks
  (=.note=, =.issue=, =.advisement=, =.algorithm=, =.data=), and
  consider dropping spec-status / Bikeshed UI rules
  (=.outdated-warning=, =.annoying-warning=, =.edited-rec-warning=,
  =.amendment=, =.correction=, =.addition=, =.codepoint=, =.uname=,
  =#toc-theme-toggle=, =.toc-sidebar=).

** Design

Open design and compatibility decisions to weigh before writing code.

*** Options compatibility chart                                   :options:

=:options-alist= ordering, =:type=, and =:safe= predicates are now
tidied and pinned by tests.  What remains is charting compatibility
with ox-html for each option and deciding whether to replace remaining
string options with =*-function= ones.  Known divergences to chart:

- =:html-link-use-abs-url= (and =:html-link-home= on file links) is
  deliberately omitted in =org-w3ctr--link-path=.
- The legacy home/up bar emits our own =<nav id="navbar">= markup,
  deliberately not ox-html's =<div id="org-div-home-and-up">=.
- =:html-home/up-format= keeps its ox-html keyword compatibility
  (=HTML_HOME/UP_FORMAT=, =newline=); =org-w3ctr-home/up-format=, a
  bare =format= string, is the natural =*-function= candidate.
- =org-w3ctr-metadata-timestamp-format= drops ox-html's =%a= weekday
  abbreviation (deliberate).
- Special blocks: with user attributes
  =org-w3ctr--special-block-builtin= replaces the type class instead
  of concatenating it as ox-html does (=class="user TYPE"=) --
  deliberate (explicit over implicit).
- Maximum flexibility is the rule for example and source blocks:
  =#+attr__:= / =#+attr_html:= replace the whole attribute list, so
  dropping =example= also drops the W3C box and its "Example N"
  counter; write =[example foo]= to keep both.  A captioned src block
  gets =class="example"= only when the author supplies no attributes
  (the class positions the self-link and hosts the caption box).

** Later

Deferred features, architectural cleanups, and low-priority notes;
pick up when a concrete need shows up.

*** Cross-file link resolution (crossrefs)                           :link:

Resolving =[[file:other.org::*Heading]]= / =::#custom-id= to an anchor
in the target document, with a project-scoped persistent cache.

*** Drop the =ox-publish= dependency                                 :link:

Replace =org-publish-file-relative-name=,
=org-publish-resolve-external-link=, and =org-publish-org-to= with
local implementations.

*** Dependency analysis                                              :arch:

Charting how far ox-w3ctr leans on Org and mapping the internal =t-*=
call graph.  Final global-optimization and cleanup task.

*** Self-links on literal blocks (deferred)                        :blocks:

Headlines and captioned src blocks emit =<a class="self-link">=;
example blocks do not, and the coderef-target rule (2026-10-17)
deliberately skips it.  The open question is the gate.  The block's id
(a =#+name:= that becomes an id, or an explicit attribute id) is the
only condition that is both explicit and free of invented syntax;
reusing a begin-line switch (=-n=, =-k=) would make a coderef or
line-number switch control presentation.  Placement is the
=.example > a.self-link= slot (top right), as in a captioned src
block; do not use =.marker=, because the automatic =.example::before=
counter would duplicate the example number.

*** Descriptionless internal links                                   :link:

=org-w3ctr--link-to-headline= synthesizes the section number (or
exported title when unnumbered) for a link without a description,
while =org-w3ctr--link-target= emits the placeholder ="No description
for this link"=.  Revisit if explicit descriptions are ever required
across internal links; also note =org-w3ctr--link-org-files-as-html=
rewrites =.org= only (not =.org.gpg= as ox-html does).

*** Src-block feature gaps vs ox-html                                 :src:

Dropped when forking (judged low-value for W3C TR output).  Revisit
later:

- Line numbers and =retain-labels=.  Coderef links exist in a reduced
  form: =[[(label)]]= points at the defining block's id, the label
  text is stripped from the code (as ox-html does), and the =-r=/=-k=
  switches are not implemented.
- =:html-wrap-src-lines=, =:html-klipsify-src=, and
  =#+attr_html: :textarea=.
- Listing number in captions.
- example-block fontification / line numbers.  The token list
  (=org-w3ctr--fontify-dispatch=) is where line numbers would be cut,
  without touching any engine.

*** Arbitrary keyword support (weigh carefully)                   :keyword:

Every backend drops an unknown =#+KEY:= line; =org-w3ctr-keyword= only
handles H/HTML, E, D and TOC.  Emitting arbitrary keywords by default
is the wrong default: keywords are metadata, not content (the corpus
carries =#+TMP:= in 55 documents), and there is no W3C element or
class for them.  The explicit hatches already exist: =#+HTML_HEAD:= /
=#+HTML_HEAD_EXTRA:= for the head (including =<meta>=), =#+HTML:= and
export blocks for raw body markup, =#+E:= / =#+D:= for computed
output.  If a repeated need appears, the only shape that keeps
"explicit over implicit" is an opt-in alist (key -> format string or
function) consulted after the built-in branches, with a test for
mapped/unmapped/built-in precedence.

*** Export entry fast path                                           :perf:

Measured 2026-10: ~78% of corpus export time is =find-file-noselect='s
per-document org-mode init, not the backend.  A raw-read path
(=insert-file-contents= + =buffer-file-name= + =default-directory= +
=org-export-as=, no =org-mode=) is byte-identical (=norm= across the
57 docs) and 4.4x faster (9.3s → 2.1s).  Apply it to the batch/corpus
path (yynt's =yynt--do-export= already does this); per-document the
saving is ~0.1s, so it only matters at batch scale.  Not the backend's
job -- an Org invocation concern.

*** Client-side highlighting                                      :fontify:

The server-side engines (=font-lock=, =shiki=) are done (2026-10).
Rather than building a full third engine, this can reuse the =plain=
(or =nil=) fontify path plus a =<head>= injection hook (such as
highlight.js or Prism) gated on a body-usage flag like
=org-w3ctr--has-math-p=, since =org-w3ctr-template-1= already renders
=body= before =org-w3ctr--build-head=.  Two details to coordinate:
=language-LANG= is already emitted on both blocks and
=inline-src-block=, and client language aliases / theme backgrounds
must not clash with =assets/style.css= (=pre > code= and dark mode).
Still waits for a concrete need since it introduces a browser
JavaScript dependency.

*** Special-block custom elements: a component cookbook        :doc:blocks:

The =:html-special-block-custom-elements= registry (=:template= for
Declarative Shadow DOM, =:src= and =:script= for the =<head>= scripts)
is the declared seam for authoring W3C components, and that is where
the mechanism stops: no =org-special-block-extras=-style block DSL (a
=defblock= macro that =read=s the block header and =eval=s raw HTML)
is planned.  What belongs in the docs instead is a cookbook of correct
component patterns for Org's always block-level =<p>= light content:
style =:host= and reset =::slotted(p)= for inline components, wrap
=<slot>= in a flow container for block components, route named slots
with =#+attr_html: :slot NAME=, and choose =:src= vs =:script=.  Theme
through CSS custom properties (=--w3c-*=), and, as optional sugar, map
a block's =:parameters= (=#+begin_x-badge :variant warn=) onto element
attributes.  For CSS-only / Light DOM components, consider extending
the default =head-function= with =:css= (deduped =<link
rel="stylesheet">=) and =:style= (inline =<style>=); for
high-frequency components, prefer Light DOM + =:css=/=:style=, a
=<link rel="stylesheet">= inside DSD =:template=, or =:src= with
shared =adoptedStyleSheets= rather than repeating large inline
=<style>= blocks per instance.

*** SVG global font cache                                            :math:

=svg-by-mathjax= uses =fontCache: 'local'=.  MathJax's =fontCache:
'global'= shares one =<defs>= per document (~1.9x smaller on a
100-formula sample).  Tried and reverted; revisit if SVG output is
kept.

*** Fontify =font-lock= face-slug memoization                :fontify:perf:

From the 0.2.18 review (not urgent): only if profiling flags the
font-lock engine, memoize =org-w3ctr--font-lock-face-slug= per export
(the state already has the =(cache . shiki-languages)= pattern).

*** Fontify palette hue differentiation                       :fontify:css:

In =org-w3ctr-fontify-palette=, the slugs =m= (constant), =v=
(variable), =o=, and =n= (number) currently share the exact same blue
(=#0550ae= light / =#79c0ff= dark), and =s= (string) is also a blue
shade.  The palette is intentionally restrained and passes WCAG AA
4.5:1 on all six code backgrounds, so this is low-priority; if numeric
literals and variables feel too similar in dense expressions, nudge
=n= (or =s=) to a distinct hue that still passes
=org-w3ctr--fontify-stylesheet-shipped=, then regenerate via
=org-w3ctr-fontify-update-stylesheet=.

*** Other transcoders take CONTENTS as =string= with no nil guard  :blocks:

ox.el prunes math under =tex:nil=, so an element whose only content
was pruned arrives with nil CONTENTS -- =org-w3ctr-paragraph= (fixed
in the LaTeX pass) and the markup objects (=org-w3ctr-bold=,
=org-w3ctr-italic=, =org-w3ctr-underline=, =org-w3ctr-strike-through=)
now normalize nil to "" (as =org-w3ctr-special-block= already did).
The remaining transcoders declare CONTENTS as =string=; guard one when
a nil-contents case shows up.

*** Unnamed elements get a fresh random id on every export           :refs:

With no explicit label, =t--reference= falls back to =t--get-reference=
(vendored from =org-export-get-reference=), which mints an
=orgXXXXXXX= id from a random number.  Four of the 57 corpus documents
hold such ids (=verify-corpus= counts them in =refs=), and an anchor
into one is not stable across exports.  Never diff raw export hashes
-- compare the normalized =norm= (see the verification skill).  Either
the author gives every referenced element an explicit =CUSTOM_ID=, or
the back-end derives a stable id -- see Non-goals.

** Non-goals

Deliberately out of scope by design.

*** Option validation

Checking user-supplied export options and customization variables for
well-formedness.  Options are trusted as given; the back-end verifies
explicit markup only (attributes, block parameters), where malformed
input fails loudly.  Exception: the fontify options (face tables,
palette, policies, face fallback, language alist) are already checked,
since a typo there silently changes the highlighting.

*** Own export framework: streaming renderer / half-parser

Replace =org-export-data='s bottom-up string building and
=org-element= parsing with a single-pass, head-to-tail renderer over a
partial parser.  It means dropping the Org export contract -- filters,
=:exported-data= memoization, string-returning transcoders, re-entrant
call sites -- not optimising =org-export-data=.  The ceiling is small:
the backend is only ~12% of export time (see next item).

*** Backend micro-optimization

Don't over-optimize: the bottleneck is not the backend.  Measured
2026-10 over the 57-document corpus (time, not allocation):
=find-file= + org-mode init ~78% (avoidable with raw read +
=org-export-as=, no =find-file=), =org-export--annotate-info=
keyword/macro preprocessing ~10%, parse-tree ~4%, backend transcode
walk + transcoders + fontification ~12%.  ox-w3ctr is already faster
than ox-html.

*** LaTeX engine fallback chain / extra client options

Unlike =fontify= (which routes across many programming languages and
falls back through =org-w3ctr-fontify-engines=), LaTeX has one syntax,
so explicit =:with-latex= selection (=mathjax=, =mathml-by-mathjax=,
=svg-by-mathjax=, =verbatim=, =custom=, =nil=) beats silent fallback.
Alternative client-side renderers that read =\(...\)= / =\[...\]=
(such as KaTeX auto-render, local/mirror MathJax, or suppressing
script injection) already need only overriding
=org-w3ctr-math-head-function= (or =org-w3ctr-mathjax-config=),
without touching =org-w3ctr-math-custom-format-function=.
